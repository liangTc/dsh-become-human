# 任务看板、关注事项与结果反思

[返回首页](../README.md) · [使用](USAGE.md) · [架构](ARCHITECTURE.md)

> **测试版本 · 尚未开发完成。** 本页能力随 [`0.7.0-beta.5` Prerelease](https://github.com/liangTc/dsh-become-human/releases/tag/v0.7.0-beta.5) 交付。已完成一次真实事项研究、来源笔记、规则反思及主人要求分享后的手机实收闭环；该次学习只覆盖部分问题，不能代表完整内容质量或长期稳定性通过。

**Human → 任务看板** 是统一入口：任务总览集中呈现实际执行，目标、定时、文件与工具页面保留原管理操作；关注事项、自我状态与反思收纳在同一侧栏。用户与 Agent 沿用原唯一 Session、有效 IM 绑定和调度器。

## 实际任务看板

汇总当前保留的自主任务、目标计划、定时任务、工具作业与文件产物，按“待执行 / 执行中 / 需处理 / 已结束”分列。支持关键词、类型、状态和更新时间范围筛选，服务端分页；统计按顶层记录去重，目标已收纳的自主任务不重复列出。自动刷新不调用模型、不推进任务。

### 默认简洁，按需展开

初次打开显示简洁任务列表：每行只保留时间、名称、类型、真实状态和步骤进度。点击单行展开原因与操作，也可使用“展开本页全部 / 收起全部”；需要按状态分列时可切换“分栏看板”。搜索保持可见，类型、状态和时间收进“更多筛选”，已生效条件仍显示摘要。

目标列表、目标步骤、执行尝试与活动时间线默认收起。执行详情保留一段当前结果，具体经过按节点展开，并提供全部展开与收起。编号、原始检查点和计量字段放在详细层级，避免初次阅读被技术信息淹没。同一页自动刷新保留展开状态；切换 Session、筛选或分页后重新收起，避免沿用另一组记录的状态。

- 目标展开实际步骤及其关联执行记录；模型请求和重试显示为“执行尝试”，不表示新增子 Agent 或并行思考线。
- 任务详情可核对执行阶段、失败原因、调用用量、笔记编号与文件回执。任务执行结束、目标验收、渠道接受、手机实收分别记录。
- 目标失败需到目标管理明确处理；独立自主失败任务需先暂停并空闲后明确重试。未知工具结果不自动重试，写操作保持原审批流程。
- 当前数据库已清理或归档的历史不计入总数；缺失的关联执行只显示原编号及归档提示，不重建不存在的内容。只读页不会重新核验磁盘文件完整性。

打开任务看板后，可在侧栏进入目标、定时任务、报告与文件、工具与能力进行操作。关注事项的状态只管理关注意图，不直接改写执行任务状态。

## 关注与复盘

| 视图 | 主要内容 | 如何理解 |
| --- | --- | --- |
| 关注事项 | 当前单一关注、候选及等待原因、事项列表与状态 | 关注是意图，不等于已经执行 |
| 自我状态 | 当前人物配置、运行状态、能力配置、已记录承诺与待确认内容 | 这是软件记录；能力启用不等于实时连接已验证 |
| 决策与反思 | 选择摘要、关联依据、任务结果与下一步建议 | 规则反思不是模型完整内部推理，也不证明意识 |

看板打开时每 15 秒只读刷新，也可手动刷新。事项分批载入，每次 50 项，本页最高显示 1,000 项；搜索和筛选只覆盖已载入记录。未载入、未召回或未显示，不代表原记录不存在。

## 创建和整理事项

在 **Human → 任务看板 → 关注事项 → 新建事项** 填写：

| 字段 | 含义 |
| --- | --- |
| 名称、类别与说明 | 这是什么事，以及需要保留的背景 |
| 为什么关注 | 为什么值得投入注意力 |
| 预期结果 | 希望获得什么可核对的结果 |
| 下一步 | 接下来可以推进的有限方向 |
| 停止条件 | 什么情况下停止、等待或交给主人判断 |
| 重要程度 | 0–100，用于候选排序；不构成立即执行许可 |
| 下次检查时间 | 注意力候选的复查时机；不是定时通知 |

加入“关注中”前，需要填写关注理由、预期结果和停止条件，关联依据也须有效。停止条件是任务契约说明，不会被当作脚本执行；当前也不能保证准确理解和自动判断任意自然语言条件。

需要到点提醒时，应到 **任务 → 定时任务** 创建一次性或周期任务。复查时间不保证到点调用模型或向手机发消息。

### 六类事项

| 类别 | 作用与当前执行边界 |
| --- | --- |
| 研究 `research` | 满足现有学习与公开搜索设置时，可形成有限研究候选 |
| 交流 `conversation` | 借用原主动闲聊机会，仍受静默、间隔、未回复退避与话题规则限制 |
| 问题 `question` | 满足学习与公开搜索设置时，可形成有限研究候选 |
| 目标 `goal` | 保留目标意图或关联；入卡不等于创建、激活或验收分步目标 |
| 承诺 `commitment` | 保留有来源的待完成事项；入卡不等于接受现实承诺或自动执行 |
| 其他 `other` | 保留尚未映射到执行路径的事项，供后续判断 |

“研究”和“问题”使用原公开学习流程，不会获得任意工具执行权。事项内容可参与当前人物、有效记忆和目标的方向选择；当前自主选题器仍不是任意工具的通用规划器。

### 六种状态

| 状态 | 含义 |
| --- | --- |
| 待梳理 `inbox` | 已记录，尚未加入自主关注候选 |
| 关注中 `watching` | 满足条件后可参与下一次选择，不保证立即执行 |
| 暂放 `paused` | 暂时不推进，记录保留 |
| 受阻 `blocked` | 条件或结果需要处理，不能当作完成 |
| 已完成 `completed` | 该事项已结束；不替代关联任务回执和目标验收 |
| 已放下 `dropped` | 明确停止关注，记录仍可追溯 |

结束事项可明确重新打开。修改带版本检查；其他页面或 Agent 已更新记录时，草稿会保留，需要先核对最新版本。创建及变更也携带请求标识，避免把同一次操作静默重复应用。

## 单一关注与注意力选择

“设为当前关注”只记录用户指定的意图，不会启动或恢复驱动，也不自动将待梳理事项转为可执行任务。当前任务正在执行时，修改的是后续关注偏好，实际执行焦点仍保留；任务结束后恢复主人指定的关注。需要停止该方向时，可明确暂放对应事项，原取消与结果提交检查继续生效。

代码结合重要程度、等待时间、到期情况、来源和当前执行状态整理候选，再交给既有事件循环选择有限方向。主人输入、暂停、预算不足、已有任务、冷却期、未到复查时间、失效证据或待确认反思都可能使候选等待。候选顺序不构成完成时间保证。

用户聊天继续优先，所有模型工作沿用同一执行通道。看板不会自动恢复用户暂停或异常停止的驱动，不会因重新打开事项而重试旧失败任务，也不会重发未知投递。

## 用户与 Agent 共用

用户可在 Web 新建、修改、关注、暂放、完成、放下或重开事项。普通前台对话也接入了有限的看板读取、创建与修改协议；只有取得真实操作回执后，Agent 才能确认事项已登记或更新。

Agent 创建的事项标记为推断提案，不会成为主人确认事实。Agent 可以管理自己提出的事项；主人创建的事项需要主人在 Web 明确修改或结束，不能由 Agent 静默改写。普通闲聊不要求创建事项，看板操作也不能替代目标确认、补额授权或外部写入审批。

前台看板操作复用已有对话与有限步骤，不另开思考线。只读打开或刷新 Web 看板不调用模型；选择与执行任务仍可能消耗原有模型预算。

## 结果反思如何阅读

反思目前依据持久任务状态、执行尝试、有效学习笔记和本地发布记录生成规则摘要。它比较预期与实际记录，可能建议核对成果、改变方法、等待授权或暂停重复失败的方向。

必须区分：

1. **任务已完成**：执行记录进入完成状态，不能单独证明内容正确或有价值。
2. **存在本地成果或发布记录**：有笔记、文件或本地消息记录，不等于外部平台已接受。
3. **渠道回执为 `sent`**：平台接受了发送，不能单独证明手机已收到或主人已读。
4. **手机实收与用户认可**：需要实际设备确认或真实反馈；缺少证据时保持未知。

当前规则反思默认建议暂放，等待核对与反馈；说明型“下一步”不会直接作为新研究问题执行。读取反思时会重验关联笔记与来源，有效性变化后不能直接采纳旧建议，可选择不采用。

采纳建议只更新关联事项的状态或下一步，不扩大工具权限、不自动补额、不重试失败任务、不改人格。反思的“已采纳”也不代表建议已经执行或其效果已经验证。

## 当前限制与待验证项

- 看板展示可观察的软件状态、意图、方向摘要与结果证据，不展示原始 chain of thought，不宣称主观意识、真实情绪或长期人格变化。
- 文本契约与规则反思仍有限，不能替代人类对事实、价值和实际结果的判断。
- 已有一次真实前台登记、研究产出、反思处理和手机结果实收；复杂复合指令仍可能耗尽有限工具步骤，内容覆盖度和长期运行仍需继续验证。
- 既有唯一会话、单渠道、暂停、失败保留、额度与逐笔写审批边界继续适用。

## 2026-10-23 本地闭环验证

本版发布前的本地 `0.7.0-beta.5` 开发快照已完成一次 Web 新建目标 → 真实模型研究 → 有效学习笔记与记忆 → 报告预览审批 → 文件落盘的两步流程。研究先拒绝一份证据不足的资料，再读取后续候选获得直接证据；全程保留同一主会话。任务在暂停、目标暂停和服务重启后沿用原任务编号与检查点，最终按本次配置的规则达到 2/2；这不代表主人满意度或更广泛的语义验收已经通过。

本次还核对了：

- 错误内容摘要和过期版本不能通过报告审批，暂停期间不会提前写文件；恢复后实际文件与批准内容、字节数、SHA-256 一致。
- 新建开发报告被明确取消后，目标阻塞并保留失败步骤；冷却期内重试被拒绝，再次唤醒不会自动重试。该项为受控取消，未冒充自然模型故障；一小时冷却期结束后的真实重试未在本轮验证。
- 研究结果自动生成规则反思，区分执行完成、有效笔记及尚未知晓的主人满意度；Web 可查看，未自动扩权限或改变人格。
- 简洁列表、目标列表、任务详情与大脑时间线默认折叠，支持单项和本页全部展开/收起；搜索、分页和同页定时刷新已实测，展开状态与焦点可保留。浏览器验证窗口为 704 × 892，其他宽度仍需补测。
- 最终源码的 118 项隔离回归通过；隔离结果不替代真实模型、手机实收或长期运行证据。

仍有两项真实限制：公开搜索即使保留精确 HTTP 状态码并执行后备查询，Bing 仍可能返回宽泛页面；微信报告待审批通知取得 `sent` 回执，但完成通知及另一个受控测试通知遇到 iLink `-2`，保留为 `unknown`，没有自动重发。2026-10-24 用户确认只收到前一条待审批通知，未收到报告完成通知；该未知投递另记主人确认“未收到”，保留原平台状态。首条的精确次数与另一个受控通知尚未确认，手机完成通知环节未通过，不能据本地目标完成状态判为端到端全部通过。

本轮保留原微信绑定、人物配置、自主额度设置、历史失败任务、旧未知投递及旧笔记/记忆；服务恢复原每 10 分钟持续运行。此记录为本地验证，不是公开发行公告。
