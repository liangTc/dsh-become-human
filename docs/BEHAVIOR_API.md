# 行为扩展接口

当前开发源码的实验接口，需要使用匹配版本构建的测试包。运行模块提供 Cordis 服务 `humanBehaviors` 和 `humanEvents`，合同版本均为 1。注册发生在 **Human 私有运行环境**。支持通过标准 DSH CLI 安装、升级及移除扩展，重启会保留依赖和 bundle；仅安装在宿主管理环境的插件不会自动转发。Web 已提供安装、配置、启停、移除、失败恢复及读取状态入口。插件是可信代码，不是安全沙箱。

从 beta.37 起，扩展还可注册声明式页面，并在 Web 选择本机安装包。参见[页面扩展合同与示例](EXTENSION_PAGES.md)。

### 内部执行模块与外部扩展的区别

`autonomy-opportunities.mjs` 收集可行机会并重新核对待恢复任务；`autonomy-workflows.mjs` 按持久化任务类型选择行为、交流、学习或报告准备模块。两者是内部实现，保留旧检查点与统一错误记账，不是第三方插件的注册 API。新增外部行为继续使用下面的 `humanBehaviors` 合同，不向内部路由表增加业务分支。模型网关、选题/任务提示、执行与搜索发现已拆为内部模块；尚未全部成为独立可安装行为包。

beta.23 将学习机会、分享/关心机会及通用工具行为适配分别移到 `learning-opportunities.mjs`、`contact-opportunities.mjs`、`capability-behaviors.mjs`。这些模块只整理已有授权范围内的机会，或复用原能力作业；主调度继续负责单执行线、提交与恢复。原任务类型、检查点和对外注册合同不变，不新增固定人物、话题或模型额度。

`selection-context.mjs` 为选题生成视图：已校验学习笔记只提供索引与当前证据指纹，不装入旧概览、结论和批注正文。标题不能当作事实依据；选中后按执行能力重新读取所需证据和批注，来源失效照常拒绝。索引展示不增加正文记忆的使用热度。人物、当前目标参数、个人事实与来源角色保留；普通聊天和执行上下文不使用此投影。这里没有新增单次 token 或上下文准入上限。

目标机会中的 `commitment` 带当前目标 ID、步骤状态、完成数、总数和 `executionComplete`，来源为实际持久回执。模型可以等待，但不能根据已知答案或旧相似任务推定当前步骤已经执行。完成步骤与主人最终验收继续分开。

## 生命周期

提供方停用或缺失时，已有未完成行为任务保留检查点并挂起，不取消或重做。恢复相同定义后沿用原任务与输入；定义指纹变化则继续等待显式重新规划，不能直接拿旧计划执行新逻辑。暂挂的旧任务不会阻塞后面的可恢复任务。来源、人物、目标、权限和结果提交仍需原有校验；失败及未知外部结果不会因此自动重试。

`register(id, descriptor)` 返回注销函数。ID 唯一，定义版本为正整数。descriptor 包含 `title`、`description`、受支持的 `inputSchema`、同步的 `opportunities(agent, snapshot)`、可选 `available(agent)` 和异步 `execute(agent, input, context)`。

机会包含 `question`、可选固定 `input`，以及可选 `eventIds`；后者必须来自本次 snapshot 中的插件事件。不得在生成机会时执行网络或写操作。snapshot 提供 `now`、`settings` 和本次读取的待处理 `events`。每个提供方最多返回八个机会，单次选择最多展示三十二个机会；更多提供方的公平调度和容量仍需后续验证。核心将机会与现有任务方向一起提供给选择模型；模型返回选择和有限计划，输入再次按 schema 校验。固定目标的方向和输入由内核从已授权机会装配，不要求模型重复抄写；自由方向仍需模型生成，显式不同输入仍被拒绝。完整计划通过后才登记执行任务。模型可以等待。当前输入 schema 复用能力接口支持的 JSON Schema 子集，并非任意 JSON Schema。

模型使用每个机会的 `opportunityId` 返回选择，不使用目标、行为或事件的 ID。拒绝诊断区分顶层结构、计划结构与未知机会编号，不保存原始模型正文。

beta.17 将机会引用的当前事件正文放入选题数据的 `pluginEvents`，按 ID 去重。只读取相关事件；不会推进轮换、领取事件或授予新权限。来源注销、版本变化、到期或属于其他会话时只返回不可用标记，不暴露旧正文。模型仍可 WAIT，选中后仍重新校验。

提供方已给出固定 `input` 时，该机会的方向及参数作为一个整体，`fixedDirection=true`；模型只需选择编号并说明价值，内核沿用提供方方向与固定参数，显式改写方向被拒绝。未绑定输入的自由机会仍由模型生成具体方向和参数。此规则不固定任何人物、兴趣或答案，也不使事件文字成为用户命令。

执行经历保存关联事件的来源和指纹；开发测试标记从事件原文追溯，不依赖模型是否在任务名称里保留标记。缺失来源的新经历不进入成长；旧误分类记录在读取时重新检查，原记录不删除。正常队列到期清理不抹掉已保存的经历来源；明确撤回经历来源仍使其失效。

## 相关经验与方法应用（beta.19）

experience-recall.mjs 按当前问题、行为和目标关联筛选有效经历与方法；不存在匹配时仅保留最近有效经历，不把不相关方法填满窗口。召回是词项/结构排序，不证明方法适用。扫描全部元数据而只保留有限结果，大历史容量仍待验收。

选择输出可以在顶层携带 strategyUses: [{id, basis, application}]（最多三条），字段必须引用本轮 experience.strategyHints 中的编号与内容指纹；application 只描述此次用法，不提供详细推理。可以省略全部方法，WAIT 不声明采用。该字段位于 plan 之外，不改变既有行为输入合同。

执行上下文新增只读方法数据 strategies。通过 context.request(messages) 调用模型时，内核把仍有效的方法作为明确标注的 Agent 暂定认识提供给执行器，并记录请求编号；它们不是主人指令、额外权限或旧失败重试许可。模型流发起及终态记录不等于模型实际遵循方法；完成仍需行为自身核验产物。

应用绑定按任务与轮次幂等，保留真实结果和未知状态；源反思撤回或证据失效后重新读取时遮蔽派生文本。管理读取 kind: 'experience' 支持 query，并返回 strategyApplications（默认20，最多100）；导出保留有效引用，受管删除清除对应记录。统计只覆盖最近100条记录中的有效项，单独排除开发结果，不宣称因果改善或主人满意。

机会中的 inputContract 报告参数状态：fixed-input-validated 表示固定输入已经按当前 schema 和定义指纹校验，空对象也是合法完整输入；model-plans-input 才需要模型规划参数，unavailable 不可选择。此状态不强制选择，执行仍重新校验权限与定义。

## 安装与配置

### 首个独立内置行为包：经历回顾（beta.24）

`dsh-human-experience@0.1.0` 将“何时回顾经历、提交暂定认识与下次方法”的行为实现拆出，可使用标准 DSH 包安装；源码在 `plugins/become-human/behavior-packs/experience`。仓库运行 `node scripts/package-behavior-packs.mjs` 后得到独立 `.tgz` 与 SHA-256 文件，再从 Web 行为扩展入口安装。本包是测试版本，未发布 npm。

| 状态 | 行为来源 |
| --- | --- |
| 未安装 | Human 随附的兼容实现 |
| 已安装并启用 | 独立扩展包；不会重复注册内置版本 |
| 已安装但停用 | 不提供该行为，旧检查点保留；其他活动可继续 |
| 卸载 | 恢复随附实现，历史经历与反思保留 |

这是渐进拆包：独立包拥有行为代码，而经历存储、证据校验、调度、模型网关和权限仍归核心。经历包移除后恢复随附实现；学习包移除后保留旧数据并挂起相关任务，不恢复隐藏学习执行。聊天、报告和部分数据兼容路径尚未全部独立安装，具体学习包合同见本页后文。

包通过 `dsh.human.replacesBehaviors: ["reflect-experience"]` 声明接管；当前仅开放这个迁移槽位，不允许覆盖任意内核行为。一个槽位只能由一个已安装 bundle 接管；停用节点不解除归属，卸载 bundle 才恢复内置实现。声明来源是实际安装清单，而不是模型或人物设置。管理操作会核对运行时行为目录，下载成功但未实际注册、或停用后仍注册，均视为失败并进入恢复流程。DSH bundle 新增节点使用 `insert` 声明。

新服务 `humanExperience` v1 固定作用于当前唯一主会话：`recent({limit})` 只返回有效经历，`hasReflection(id)` 检查有效反思，`reflect(input)` 使用原证据校验和幂等请求。它不暴露其他会话选择器，不提供修改人格、凭据、权限或配额的接口。开发经历、撤回证据及反思自身仍不能成为新的独立成长证据；提交认识不等于它已被证明有效。

### Web 管理（本地 beta.20）

进入 **Human → 设置 → 更多设置 → 工具与技能 → 行为扩展**。可以安装或更新、停用、启用、编辑节点配置及移除扩展，查看最近操作的结果。声明 public-sources 编辑器的扩展提供来源表单，其他扩展使用高级 JSON；两者采用相同配置版本与保存流程。

安装来源支持明确版本 `包名@1.2.3` 或服务器本机 `.tgz` 绝对路径，不接受 `latest`、Git 地址、远程安装包链接或额外命令参数。目录必须是 Human 独立后台的 profile，宿主插件列表不受影响。这里不是上传文件；远程使用 Web 时，本机路径指服务器机器。安装前需确认信任扩展代码。

管理器调用标准 DSH 插件 CLI，安装时关闭包生命周期脚本。扩展仍是可信本机代码，停用不构成安全隔离。只接收包含 DSH bundle 的 Human 扩展，节点须为 `human-extension.*`；支持普通节点数组及标准 `insert` 层，不允许覆盖受管基础节点。同名包再次安装是更新，配置覆盖保留，不自动迁移不兼容的扩展配置。安装包限 20 MiB、解压限 32 MiB；首版接受普通文件与目录，不接受链接或 PAX/GNU 扩展头。

操作串行进行：保存幂等请求 → 暂停并停止后台 → 再次核对配置版本 → 保存恢复快照 → 安装或修改 → 检查节点与版本 → 启动 → 按原状态恢复。原本暂停或存在失败保护时不会恢复模型。响应丢失时相同请求 ID 返回原记录，不会再安装一次。移除只清理包及其配置覆盖，历史会话、任务、事件和回执保留。

### 失败恢复（本地 beta.23）

安装前保存依赖清单、锁文件、bundle 配置及 Human 覆盖配置，并记录原主会话和直接依赖版本。正常捕获的失败在文件状态可确认时，尝试用原锁文件和本地缓存恢复依赖，再恢复配置并启动原会话；**恢复后自主保持暂停**，失败原因仍保留。已有依赖却缺少锁文件时，在包变更前拒绝操作。恢复不回退数据库、聊天、记忆、任务、投递记录或扩展已经执行的外部操作。

自动恢复失败时阻止普通启动与新的扩展修改；文件状态可确认且未被其他操作改变时，Web 显示“恢复安装前状态”供显式重试。恢复使用相同快照，禁止生命周期脚本，不自动重做失败的安装。配置被其他进程改动、快照不匹配或主会话不一致时拒绝覆盖；缓存不足则保留失败，不能保证离线恢复成功。快照保存在管理器私有目录，不通过页面返回文件正文。

进程在包变更中被强制终止、没有取得确定的变更后文件状态时，只保留中断记录并阻止启动，需要人工核对；**不自动猜测或回放**。成功恢复会清理快照，操作记录保留。不要同时用其他 CLI 修改同一 profile。受控仓库版本下载和本机安装包的真实失败恢复已有记录。2026-11-04另完成空扩展缓存下载公开依赖及受控认证仓库短测；实际组织私有仓库、其他操作系统和任意第三方扩展仍未全面验收，详见[测试状态](TESTING_STATUS.md)。

### 仓库与兼容边界

本地 beta.33 补充空依赖配置的恢复：安装前没有任何依赖时，将失败安装留下的 `node_modules` 移到同一 profile 下的 `.human-recovery-modules-*` 留存目录，再离线恢复。这样不会让新包残留的内部锁文件参与旧配置恢复；留存目录记录在操作结果中，不自动删除。已有依赖的配置仍按原锁文件与缓存恢复，缺失缓存继续阻塞，不能把这个修复理解为绕过仓库校验或从网络自动补齐依赖。

状态与行为/工作流目录读取在连接中断或超时后，最多对同一后台进程重读一次；进程或登录态变化则停止。每次此类读取限时10秒，其他请求保留45秒；业务拒绝、无效响应及写操作不自动重试。读取失败不改变已经提交的安装结果。管理日志分别记录连接失败、超时和恢复，不再统一丢失为未知请求错误。

Human 行为扩展需要 DSH bundle、`human-extension.*` 节点及与当前 Human API 相符的实现。普通 npm 工具库、宿主 Web UI 插件或任意 DSH 插件，不会因“能被包管理器下载”就自动成为 Human 行为。必须在原会话启动后检查实际行为或工作流注册，而不是只看依赖列表；当前对声明接管的内置行为、工作流会进行运行注册核验。

包名安装使用后台 profile 的标准包管理器仓库设置。Web 暂无独立的私有仓库登录界面，也不会自动复制宿主模型或 IM 凭据。受控短测使用专用 `.npmrc` 的 scoped registry 和仓库地址限定令牌；令牌未发往不同端口的安装包服务，生命周期脚本未执行。这不是任意组织认证、SSO、证书或环境变量组合均已通过的结论。密钥不要填写到扩展安装来源、节点 JSON 或公开日志中。

仓库凭据失效不等于本地缓存失效。指定版本所需元数据及包内容仍可从缓存或既有下载地址取得时，包管理器可能在出现 401 后继续完成安装；**安装结果不能充当凭据有效性检查**。没有缓存的认证请求失败时，管理器保留失败并尝试离线恢复旧版本、配置与停用状态。

### 手动 CLI

示例包位于 [human-signal-plugin](examples/human-signal-plugin/README.md)，可以在该目录打包后安装。先在 Human 的运行配置中核对后台数据目录和 profile，并暂停后台；以下占位值必须换成该后台的实际值，不能误装到宿主管理 profile：

```powershell
$env:DSH_HOME = '<Human 后台数据目录>'
dsh plugin --profile '<Human 后台 profile>' add '<扩展包.tgz>'
```

Human 启动时保留 profile 的依赖、扩展 bundle 及其他包管理字段，并将受管运行 bundle 放在最后。扩展 bundle 的 Cordis 节点使用 `human-extension.<名称>`；需要覆盖配置时，写入该 profile 的 `human-extensions.patch.yml`：

```yaml
- id: human-extension.signal-example
  config:
    signals: []
```

此文件最多 64 个节点，仅支持 `id`、`config`、`disabled`，不允许修改受管 Human 节点。生成的 `cordis.patch.yml` 会在启动时重建，不能在那里保存长期自定义配置。配置无效时启动明确失败，不静默重置。安装、升级、禁用或移除后重启后台；更新实现语义或输入合同必须递增定义版本。

```powershell
dsh plugin --profile '<Human 后台 profile>' remove dsh-human-signal-example
```

卸载后移除该扩展对应的配置项，重启核对行为与事件源目录。历史任务及事件回执保留；卸载不会自动清空主会话。`add` 的离线安装参数不应直接用于 `remove`。此流程不覆盖任意 DSH 插件的兼容性，也不自动导入宿主凭据或扩大工具授权。

## 外部事件

### 可选公开来源采集（本地 beta.22）

`ctx.humanSources.register(id, {url, title, intervalMs, emitInitial, format})` 为可信扩展注册一个明确指定的公开来源，返回 `check()`、`status()`、`get(eventId)`、`pending()`、`dispose()`。`format` 为 `auto`（默认）、`feed` 或 `document`。扩展需要声明 `inject: ['humanSources', 'humanBehaviors']`，并在释放时注销句柄。可安装参考见 [公开来源观察扩展](examples/human-public-source-plugin/README.md)。没有默认订阅地址；内容不能自行注册更多来源。

这层只读取公开内容、比较响应指纹和生成事件，不调用模型、创建学习笔记或自动联系用户。选择阶段仍决定是否值得观察。默认首次只建立基线，`emitInitial: true` 才提交首次观察；地址、标题或采集配置改变后旧事件指纹失效。注册期间以配置间隔采集，即使模型暂停也只入队，不恢复驱动；停止采集可停用对应来源，或禁用/移除扩展并应用。

最低间隔一分钟、最多一天、最多32个来源；每15秒扫描一次到期来源，最多三个来源并行读取，单个来源共享同一次读取。失败后指数退避，最长一天。未变化不入队；状态查询不抓取。保留上次基线、检查时间、失败分类和下次时间；重启继续原计划。队列满时保留完整待发布事件，不提前推进基线；同一发布在进程中断后重投仍保持相同键、时间及正文。一天内未发布的事件到期后记录并放弃，不把过期数据换时间冒充新变化。

公开读取器 `public-document.mjs` 与学习解释分开；每次跳转仍执行 URL、公网 DNS、固定地址与体积检查，不带凭据或浏览器登录态。截断响应不能建立基线。诊断只保留限定错误码、阶段、耗时及候选序号；DNS 和连接失败可以分辨，不保存任意异常文本。

beta.20 按 RSS 2.0、Atom 和 JSON Feed 1/1.1 的条目解析，普通网页按可见文字比较。Atom/JSON Feed 使用条目 ID；RSS 优先 guid，再用链接，最后以标题降级标识。RSS 缺少稳定 ID 时同名条目无法可靠区分，宜使用带 guid 的来源；仅 description 且无 guid、链接或标题的条目不在支持子集内。

条目顺序、频道元数据、发布日期单独变化、可见空白及不可见脚本变化不生成新事件；标题、正文、正文链接、作者或标签变化仍会记录。同 ID 内容冲突拒绝本次观察，不覆盖旧基线。条目退出当前订阅窗口不当作删除事件，原样回归不重复通知。上述为确定性的结构降噪，不是模型语义去重；广告或动态可见内容仍可能产生变化。

每次最多 256 条、每个来源记住最多 4096 个条目标识，达到容量明确停止更新并记录 `SOURCE_FEED_HISTORY_FULL`，不会静默淘汰旧标识导致重复。XML 采用有界子集，拒绝 DTD、外部实体、畸形或不支持的结构；不下载 Atom 外部内容、附件或翻页。属性引号内的字面 `>` 暂不支持。规则参考 [RSS 规范](https://www.rssboard.org/rss-specification)、[Atom RFC 4287](https://www.rfc-editor.org/rfc/rfc4287) 与 [JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/)，不声称完整兼容其全部可选结构。

事件保留来源标题、条目 ID/地址、当前与上次内容摘要值、完整响应摘要值及最多1600字符的预览，标明截断与未核验状态。发布方日期单独标注，观察时间仍是实际抓取时间，不将历史发布日期当作新近发生时间。HTTP 成功只证明取得内容，不证明内容真实或对主人有价值。

批量变化逐条持久发布，队列满时留下剩余条目的原始键、时间和正文；中间崩溃可继续，不重新生成已发布条目。状态增加解析格式、已知条目数、待发布数、降噪次数和过期丢弃数。解析规则或配置指纹变更会建立新基线，旧配置事件失效；默认首次静默，升级不自动补发历史内容。

事件源使用 `ctx.humanEvents.register(source, {version, title, inputSchema})`。返回句柄包含 `publish`、`pending`、`get(eventId)`、`dispose`；插件通过 Cordis `ctx.effect` 管理注销和事件监听释放。`publish` 输入为：

```js
source.publish({
  key: 'stable-change-id',
  occurredAt: observedAt,
  expiresAt: observedAt + 60 * 60 * 1000,
  payload: { title: '具体变化', detail: '需要核对的外部内容' },
});
```

时间使用毫秒；同一来源的变化键必须稳定。重投保留原时间、有效期和内容，相同事件只入队一次，同键不同内容拒绝。最多 64 个来源，载荷 8 KiB，单来源最多 64 条待处理事件，单 Human 最多保留 2048 条未过期事件；有效期由适配器提供，最长七天。队列满时明确拒绝，不丢弃已有任务。过期记录在下一次新事件写入时清理；已被清理或过期的引用不能执行。

事件持久化为未核验外部数据，不等于主人指令或新的权限。空闲且持续驱动开启时可请求唤醒，最短间隔一分钟；暂停、失败保护或执行中只留队，不恢复驱动、不打断用户输入。选择和执行仍计入自主额度。这里提供同进程发布接口，Webhook、文件监听或其他外部服务需要自己的适配器，不默认开放 HTTP 接收端口。

行为从 `snapshot.events` 提供机会，并在该机会的 `eventIds` 中声明依赖；事件源句柄只读自己的有效事件。目标也可以直接调用同一行为，因此事件行为应声明同步的 `eventsForInput(input)`，返回依赖的事件 ID 数组。执行前内核绑定并领取这些事件；有现存声明时必须保持一致。此函数应纯粹、确定，不执行 I/O。

状态为 `pending → claimed → handled`。只领取选中的引用，WAIT 或其他行为完成不消费该事件。等待审批或挂起保留领取状态；完成、失败或结果未知均终结该次消费，`handled` 不表示业务成功。执行异常保留领取和失败记录，不重新投放自动重试。任务终态与事件确认在同一事务提交；重启不会将已处理事件重新入队。来源注销或定义变化阻止旧引用执行；匹配版本重新安装可以恢复尚未过期的待处理数据。

当前每轮最多读到 16 条插件事件、同一来源最多八条。`pending()` 独立预览当前来源最多八条，不因其他来源占满全局窗口而返回空；状态里的 `available` 仍是当前全局窗口数量。

执行上下文包含 `task`、`signal`、`valid()`、`turn`、`epoch` 和 `request(messages)`。需要模型时必须使用 `request`，它经过原单执行线、供应商路由和自主额度预留，不开新 Session；不能并行调用多个模型。返回包含 `text`、`rid`、`usage` 等字段的对象；调用完成不等于任务产物通过校验。长操作必须遵守取消信号，提交前调用 `valid()`。可信插件自行绕开接口的副作用不受沙箱保证。

返回 `{status, summary, ...receipt}`，status 为 `completed`、`waiting`、`failed` 或 `unknown`；摘要最多 1200 字符、整个结果最多 32 KiB。结果是执行回执，不自动代表外部事实正确或用户满意。需要真实写操作时通过统一能力接口提交，并等待既有预览与批准；不以结果文本伪造成功。定义撤销、版本变化或上下文失效会拒绝旧执行结果。

## 候选窗口与轻量理解（beta.15）

插件事件按来源分组、组内按上次进入窗口的顺序轮换；行为机会按提供方或内置类别分组，最多展示 32 条。一次新的自主调度扫描推进持久游标，状态查询不推进；进程重启后继续原位置。内部事件与插件事件交错组装，避免旧内部积压完全遮住外部变化。已失效来源与候选不再占用游标记录，正在等待、已经领取和已经处理的状态不被轮换改写。

该机制保证有限稳定候选集有机会进入窗口，不强制模型选择、不自动重试失败，也不增加调用频率。窗口构建早于最终模型预算准入，进入窗口不能当成模型已经阅读或执行；来源仍须在过期前产生可行机会。提供方不返回的动作、动态变化的候选集、长期持续高负载不在有限公平测试的保证内。

示例扩展 0.3.0 可通过 `reviewWithModel: true` 启用一次模型的轻量事件理解：只形成暂定观察、可能价值、待确认问题和下一步建议，保存在任务回执。无需学习笔记、深研究、报告或主动联系。建议不会自动执行；无来源核验的内容持续标记为推测。它是可安装的参考行为，不会随内核升级默认开启。

## 一个无外部副作用的行为

```js
const dispose = ctx.humanBehaviors.register('organize-ideas', {
  version: 1,
  title: '整理当前想法',
  description: '把当前关注的一点想法整理成一个待验证的提案，不自动发消息。',
  inputSchema: {
    type: 'object', additionalProperties: false,
    properties: { idea: { type: 'string', minLength: 1, maxLength: 400 } },
    required: ['idea'],
  },
  opportunities: () => [{ question: '是否有一个值得整理的想法？没有就等待。' }],
  execute: async (_agent, input, { valid }) => {
    valid();
    return { status: 'completed', summary: '已形成待验证提案。', proposal: input.idea, verified: false };
  },
});
// 插件释放时调用 dispose()。
```

这个示例只保存一次结构化提案，不声称已经实现想法或在真实世界行动。新增复杂行为需要自己的效果验证、取消及恢复测试。

## 能力与目标

显式允许自主使用的能力自动生成 `tool.<能力ID>` 行为。能力请求按任务 ID 幂等，等待审批或恢复时使用原作业，不重新生成输入。相同操作的失败记录不会因新任务编号绕过：普通失败需原任务或目标步骤的明确重试；不明写入结果保留 `unknown`，不自动重放，也不因普通重试按钮跳过人工核对。工具原始返回保存在作业中，自我上下文仅带有未核验标记的有限预览。自定义 MCP 的授权字段为 `tools[].autonomous`；DSH 自主读取在连接设置单独开启，保存到 `autonomy.toolIds`，不扩大原读取范围。发起外部模型会话的能力不自动映射。

选题上下文的 `actionContract` 根据真实可用的能力目录生成，不信任工具描述中的权限自述。只读能力为 `execute-read`；写入能力为 `prepare-approval`、`executionRequiresApproval: true`。模型选中写入机会仅准备待批准作业；批准仍校验输入预览摘要、作业版本、当前策略与有效期。目标暂停期间，已批准作业仍由原任务持有，不能被普通工具队列绕过；恢复后复用原作业。第三方 MCP 的 `readOnlyHint` 不能代替用户配置的 effect 或自主授权。

通用目标步骤：

```json
{"kind":"behavior","behaviorId":"organize-ideas","question":"整理目前的一项改进想法","input":{"idea":"待验证的具体提案"}}
```

目标仍需显式确认后激活。目标行为在选题前取得 eventsForInput 引用，失效事件明确阻塞；同一有效行为、固定输入和事件的普通机会并入目标机会，执行前明确归属，不用历史普通回执补记目标完成。没有指定验收合同的通用目标默认不要求学习笔记，但要求主人最终验收。原研究、阅读和报告目标保持兼容。行为生命周期内失败不自动重试，修改事项卡片不构成重试授权。

## 经历与回顾

终态任务生成幂等经历，区分意图、执行状态、工具回执、推测和满意度。开发测试不写入真实人格证据。`reflect-experience` 行为可以基于当前仍有效的经历提出暂定认识和下次方法，以及最多三十天的阶段角色。反思自身不会生成新的独立人格成长来源。它不改变基础身份、关系或权限；来源撤回、角色到期或主人撤回使相关投影失效。设置中的人格偏移开关仍控制较稳定倾向的自动变化。

`read {kind:"behavior-catalog"}` 返回当前可用定义；`read {kind:"experience"}` 返回有效经历和方法摘要。`control {op:"experience-reflection-withdraw", id}` 撤回一项方法回顾及其阶段角色，不删除原始执行记录。Skill 支持 `behavior:<行为ID>` 阶段，内容仅指导方法，不授予权限。

## 验证边界

`scripts/verify-behavior-core.mjs` 使用隔离 SQLite 与合成模型适配器检查选择、非学习执行、目标推进、结果回顾、取消和来源失效；它不证明真实模型能够稳定判断价值。本地真实模型已完成非学习数值计算的两步目标及暂停重启恢复；测试结果不进入人格成长。第三方行为安装、不同 MCP 服务、真实会话选择和长期人格变化需要后续实测。


### beta.21 选择来源与验证范围

当前目标的承诺索引由内核生成 `decisionFrame`；外部正文、插件描述和历史对话不能伪造其中的主人请求，也不能扩大原能力权限。模型仍可等待并说明取舍。开发标记仅隔离人格/记忆证据，不取消已经激活的测试目标。

包仓库路径已有真实 DSH CLI/pnpm 对受控本地 HTTP 仓库的版本下载、更新、幂等、拒绝与卸载检查；公共 npm、私有认证仓库及任意扩展兼容仍未验收。测试替身的后台生命周期不能代替实际服务恢复；真实 Web 的本机安装包管理另有实测记录。

## 声明式来源配置与诊断（beta.22）

在扩展 package.json 的 `dsh.human.configEditors` 声明 `[{"nodeId":"human-extension.your-node","kind":"public-sources","version":1}]`。节点必须属于本包；不支持的编辑器类型或版本回退到高级 JSON。界面不判断特定包名，也不接受远程脚本作为表单。

此编辑器适用于 `config: {sources: [{id,title,url,intervalMs,format,emitInitial,enabled}], reviewWithModel}`：每节点最多八个来源。表单支持名称、公开地址、分钟间隔、单来源启停和高级选项；未知顶层配置与其他节点保留。来源行的未知字段会拒绝，避免把拼错字段当作已生效。`enabled` 是适配器配置，调用 humanSources.register 时必须先去除；参考示例 0.3.0。手动 JSON 仍受相同服务端校验；配置冲突、私有地址、重复启用标识等在停机前拒绝。

Web 状态卡显示等待、读取中、成功、失败和停用，保留最近成功与下次检查时间。读取成功不代表事实核验或模型已关注。“立即检查”按当前来源指纹排队，每来源一分钟最多一次，重复在途请求共享读取；限频跨重启保留。它不调用模型，不恢复暂停的自主活动；已开启的自主驱动仍按原门禁决定如何处理后续变化。

关闭单个来源后注销其读取器；重新启用相同配置保留基线。修改地址、标题、间隔、格式或初次提供选项会重新建立基线；开启 emitInitial 时可能再次提供当前条目。配置变更短暂重启 Human 后台，暂未实现热更新。beta.23 增加上述有限失败恢复；包商店、通用任意 schema 表单和公共认证仓库兼容仍未完成。

## 可选学习包（beta.25）

`dsh-human-learning@0.1.0` 将旧 `research` / `learn-ai` 的机会生成、选中来源后的准备和执行顺序集中到独立包。主包不自动加载该提供方；学习包默认 `disabled: true`，还需要用户单独开启学习方式。新建 Human 的“自主活动”不再顺带开启学习。

生命周期：未安装/停用/卸载 → 不生成学习及主动知识分享，不执行已有学习步骤；旧任务持有计划并挂起、不会挡住其他可恢复任务。重新启用同一协议 → 原编号和检查点继续使用；失败任务不自动重试。旧笔记与人工批注保留，前台按需召回、普通记忆、MCP、公开读取和报告不依赖学习包。

迁移接口 `humanLearning` v1 仅接受 `{ version: 1, collect, prepare, execute }`；不用于扩展任意新任务类型。`collect` 接收脱离数据库的机会快照；执行函数接收任务、取消信号以及受当前执行线约束的来源读取、模型调用、校验提交方法，不接收原始数据库、凭据或会话选择器。安装包通过 `dsh.human.providesWorkflows: ["deep-learning"]` 声明提供方，管理器启动后核对真实目录，防止安装成功但行为未注册。重复提供方拒绝。

`read {kind:"workflow-catalog"}` 返回实际加载的迁移工作流；它不混入 `behavior-catalog`，因此不会出现在通用目标步骤的行为选择器中。旧学习目标仍使用原 `research` / `learn-ai` 类型。

该包不使用 `replacesBehaviors`，卸载也不会恢复学习内置实现。`humanLearning` 只是历史任务迁移接口；新增其他行为继续使用 `humanBehaviors`。来源/证据校验和持久化保持核心服务，扩展仍是受信任本机代码，这个窄接口不构成安全沙箱。
