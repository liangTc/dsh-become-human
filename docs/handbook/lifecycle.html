一个包可以参与多个环节。用一个 owner 注册资源，把定时、读写和清理交给对应的宿主接口。

注册哪些资源

字段使用场景
events / sources前者定义本包可发布的类型化事件，后者注册受管理的公开内容来源。
behaviors / capabilities行为提供候选和执行方式。能力封装实际工具及其输入、效果与授权要求。
pages为 React 页面注册后台方法；页面的标题、节点、前端文件和方法模式还要在包清单中声明。
schedules到期后向同一插件已声明的来源发布事件，供后续选题。
hooks根据阶段元数据更新插件自己的进度，或提交后续事件。

统一入口是 ctx.humanPlugins.register(owner, descriptor)，当前 contractVersion 和描述符的 version 均为 1。包名与 owner 相同；资源的本地 ID 以小写字母开头，最长 48 字符，可使用小写字母、数字、点和短横线。跨包引用资源时用 resourceId 生成实际 ID。

在什么阶段接收反馈？

input / selection
用户输入已提交，或开始一轮选择。可以据此更新关注事项。
result / delivery
分别表示任务产生终态结果、回复已写入主会话。确认手机收到消息需要渠道或用户端的额外证据。
feedback / memory / growth
接收追问、批注、记忆修订和成长变化等对应的事件元数据，适合更新插件自己的判断依据。
hooks: {
  result(event, {state, now}) {
    return {state: {...state, lastResultId: event.id, updatedAt: now}};
  },
}

回调同步运行，允许返回 {state?, events?} 或 undefined。输出最多 16 KiB、八个事件。每个事件形如 {source, event}，来源须属于本包。插件状态按人物及 owner 隔离。回调抛错或返回 Promise 时，宿主回滚本次贡献并挂起该回调，日志记录 plugin-hook-held。

定时、错过与卸载

规则支持 after、at、every、daily、weekly 和 cron。例如 {kind: 'every', seconds: 3600} 表示每小时提供一次机会。使用宿主的规则字段与时区。暂停、关闭自主或处于安静时段时，托管定时等待。

missedPolicy: 'latest' 将错过的周期合并为最近一次；选择 'all' 时，每个计划在每轮检查中最多补入一个仍然有效的事件。队列满时保留进度，稍后再检查。相同定义重启后沿用原定时，已完成的一次性定时不会再次触发。

在 Cordis effect 中返回 () => plugin.dispose()。卸载撤销资源注册和页面入口，原任务、记录与检查点有各自的保留规则。变更行为语义时递增其定义版本，旧检查点需要重新核对。生命周期合同 · 注册表实现
