## 优先待测试项

以下是后续顺序与验收范围，不表示本次已启动这些测试。每一项均需分别记录使用版本、环境、实际动作、结果及未发生的情形。

### 1. 全新 DSH 的原生 DeepSeek 接入 · 本轮暂缓

- 在独立的全新 DSH 数据目录中安装对应开发版 Human，验证没有 Key 时的引导与默认模型发现。
- 在宿主配置原生 DeepSeek API Key，重新检查模型，核对官方模型、有效自定义模型与凭据就绪状态；确认不要求在 Human 重填密钥。
- 分别验证需要支持的进程环境、受管凭据和 `.env` 引用来源及其优先级；凭据值不得进入前端、生成的 profile、首次设置记录或公开日志。
- 完成首次设置，检查私有后台启动、唯一主会话创建、暂停/恢复以及再次冷启动行为。
- 经明确授权后完成一次真实原生请求，核对结果、账本、取消/超时与推理档位；真实请求会产生供应商费用。
- 验证缺少凭据、无效凭据、提供商 ID 冲突、不兼容模型配置和混合路由档位冲突的错误提示与可恢复性。
- 在已有安装执行升级回归，确认原有主会话、微信绑定、记忆与用户配置保留；全新安装验证使用独立环境，不清理现有数据。

**当前阻塞与边界：** 已检查的源 DSH 未配置原生凭据。原生目录已发现，真实原生网络调用尚未验证；DeepSeek 账号登录通道不在本次支持范围。

### 2. 最新版完整真实闭环与交互

- 从新问题开始，依次核对公开搜索、有效笔记、反馈/记忆、多步目标、审批、报告与手机实收。
- 在新任务中验证子任务推进、暂停恢复、失败后明确处理、结果反思、重复提交和通知次数。
- 验证默认摘要、单节点/本页全部展开、筛选分页、刷新保留阅读状态及草稿冲突；核对统计分类与原始账本一致。
- 对 `unknown` 投递先人工核对外部结果，不用自动补发制造“通过”。

### 3. 学习、记忆与积压质量

- 比较不同主题、精确问题与跨主题搜索的有效产出率，区分搜索无结果、证据不足、格式错误和真正学得成果。
- 检查摘录与结论是否有语义支持、来源失效或撤回后的失效处理、多爱好记忆和长期话题召回。
- 覆盖超过十份笔记的分享积压，检查旧候选是否长期饥饿。
- 核对记忆整理的周期/数量触发、重要记忆保护、冷热召回、摘要原文关系、批次恢复和重启一致性。

### 4. 工具、权限与交付

- 在干净环境安装和升级，与其他插件共存；确认普通 DSH 会话与 Human 私有后台相互隔离。
- 分别接入真实 stdio 与 Streamable HTTP MCP，验证发现、授权、撤销、定义变更、超时和凭据隔离。
- 对真实非空 DSH 会话验证指定范围与“全部可见”读取，核对分页/截断；发送或取消仍需精确逐笔审批。
- 验证其他 IM、真实换渠道、手机目标/提醒命令；浏览器及窗口控制另行验收。
- 在合成数据环境验证 Windows 符号链接边界、删除/导出并发、离线备份及恢复；不能把同账户恢复视为跨机器迁移通过。

### 5. 真实时间、故障与长期运行

- 在后续专用机器上重新建立最新版完整 24 小时及多日观察窗口。旧长测提前结束及恢复后的观察不能拼接成连续运行通过。
- 实际覆盖跨日额度、周期授权到期、Cron、时区/夏令时、断网、限流、进程退出和休眠恢复；没有真实发生的项目明确标记未验证。
- 观察单思考线、计时器间隔、队列与文件增长、失败处理、投递重复、平台限制与费用记录。记录观察缺口，经过时间不等于稳定可用。
- 在开启人格偏移并取得独立真实反馈后，观察至少七天的变化依据、证据撤回、关闭、回滚与重启；不得生成虚假用户反馈，或用角色化表达认定长期人格进化。
