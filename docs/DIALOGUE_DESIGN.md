# 日常对话表达试验

beta.36 本地候选将前台聊天的表达指导合并到 `human-dialogue`。目标是让当前人物接住眼前的交流，而不是让每条消息都完成一份说明。

## 规则如何装配

- 启用 `human-dialogue` 时，前台不再重复加载兼容标识 `zhiqiu-expression`；后者仍用于主动关心、分享等原有场景。关闭前者后仍可回退到后者，用户自己的技能不被替换。
- Humanizer 完整文本继续按需提供，不为每条聊天增加独立润色调用。
- 长短由用户当前目的决定，不用固定句数判断聊天质量。事实、原话归属、记忆有效性、权限和工具回执仍按原机制校验。
- 发送前检查明确允许有交流用途的玩笑、重复确认、简短陪伴和虚拟亲近，不要求每句话都增加事实或给出方案；检查仍可能误判，因此需要真实多轮验证。
- 新情境与旧情境中的更正分开理解，检查直接对照当前输入；历史助手措辞只记录说过什么，不作为必须模仿的表达。这个判断交给模型，不按人物、日期或聊天关键词编写回复分支。

## 人物与情境示例

统一技能保留少量虚构情境及不同表达方向，让模型结合当前人格和关系决定自己的措辞。示例没有固定角色姓名、称呼或兴趣，也没有按关键词匹配的回复分支。

这不是自动生成或保存一份人物台词库。示例只是表达参考，不进入历史消息、事实记忆或关系计分；人物切换后仍以当前配置为准，不能把示例里的亲密程度或经历移给新人物。已有技能编辑机制可用来添加自己的表达示例。

## 验证方式与边界

同一真实模型、同一 Human 会话先后运行虚构多轮场景，比较陪伴、不要建议、调侃、多个兴趣、更正时间、回顾和未知细节。前后请求顺序不同，背景历史和采样也不同，因此属于前后样例比较，不是严格随机盲测，不据此计算普遍自然度提升百分比。

测试消息应按来源明确隔离，不形成真实用户经历，不发送手机镜像。保留早期失败样例和检查改写次数；最终回复成功不等于所有中间草稿都正确。结束时恢复原唯一会话的持续运行和原渠道配置。

设计参考：[Context-Aware Humanizer 的聊天指南](https://github.com/quqxui/context-aware-humanizer/blob/main/references/chat.md)和[SillyTavern 的人物/示例对话说明](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)。本次为项目内原创适配，没有安装它们的脚本、另建风格记忆库或引入新的聊天后端；原 Humanizer 的来源及许可继续保留。
